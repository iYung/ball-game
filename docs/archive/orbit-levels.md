## Orbit Levels Checklist

Design doc: `docs/design/orbit-levels.md`

- [x] Task A — `game/player.lua` — Rewrite as the orbit-ball entity. Fields: `x, y` (ball position), `center_x, center_y`, `radius`, `angle`, `direction` (+1 cw / -1 ccw), plus constants `BALL_RADIUS=10`, `MIN_RADIUS=50`, `MAX_RADIUS=300`, `RADIUS_RATE=140`, `ANGULAR_SPEED=2.4`. `Player.new(x, y, center_x, center_y, direction)` sets initial state directly (no derived radius/angle guessing — compute them from the given center in the constructor). `Player:update(dt, space_held, walls)` implements the 4-step algorithm from the design doc exactly: (1) clamp desired radius, (2) re-pivot center keeping `x,y` fixed, (3) recompute angle from `(x,y)-center` then advance it by `direction*ANGULAR_SPEED*dt` and derive the new `x,y`, (4) collision-test the new position against every rect in `walls` (circle-vs-AABB: clamp ball center to rect, compare distance to `BALL_RADIUS`; on the first hit, push the ball to the rect surface, flip `direction`, and re-derive `angle` from the corrected position). `Player:draw()` draws a filled circle at `(x,y)` with radius `BALL_RADIUS` via `love.graphics.circle`. No `Sprite`/`Input` dependency — space-held state and walls are passed in by the caller so this stays headless-testable.

- [x] Task B — `game/level.lua` — New shared module (plain functions, not a class) with: `Level.walls(level_def)` → list of `{x,y,w,h}` rects: each of the 4 boundary sides of the 1280×720 room as a full rect, except the side named in `level_def.exit.side`, which is split into two rects flanking a `level_def.exit.gap`-wide gap centered at `level_def.exit.pos`; then `level_def.obstacles` appended unchanged. `Level.mirrored_entry(level_def)` → `{side = opposite(level_def.exit.side), pos = level_def.exit.pos}` (opposite: top↔bottom, left↔right). `Level.spawn(entry)` → `{x, y, center_x, center_y, direction=1}`: a point just inside the named wall at `pos` (offset inward by `BALL_RADIUS + 4`), with the center offset a further `MIN_RADIUS` inward along the same normal. Wall thickness constant `WALL_THICKNESS=40` lives here.

- [x] Task C — `game/levels/level_1.lua`, `game/levels/level_2.lua`, `game/levels/level_3.lua` — New data files, each `return { id=N, exit={side=,pos=,gap=160}, obstacles={...} }` per the design doc: level 1 empty, exit `top,640`; level 2 one obstacle rect roughly centered forcing a detour, exit `right,300`; level 3 two jutting wall rects forming a corridor that narrows to a gap just wider than `BALL_RADIUS*2` at its choke point, exit `top,200`.

- [x] Task D — `game/scenes/level_scene.lua` — New scene, replaces `game/scenes/game_scene.lua`. `LevelScene.new(level_id, entry, sm)` extends `Scene` (`Scene.new(1280,720)` then `setmetatable`), loads `game/levels/level_<id>.lua`, computes spawn via `Level.spawn(entry or default-bottom-640-for-level-1)`, builds wall rects via `Level.walls`, creates the `Player`, and an `Input` instance bound to `space`. Draws walls as plain colored rectangles (reuse `Sprite` with no image) added to the scene's `drawer`, and the player drawn on top (register the player object itself in the drawer — it has its own `:draw()`). `update(dt)`: reads `input:is_down("space")`, calls `player:update(dt, space_held, walls)`, then checks if the player's `x,y` is outside `[0,1280]x[0,720]`; if so, computes the next level id (wrap `3→1`) and mirrored entry via `Level.mirrored_entry`, and calls `sm:switch(LevelScene.new(next_id, next_id==1 and nil or entry, sm))`. `draw()` calls `Scene.draw(self)` then prints level number + control hint text.

- [x] Task E — `main.lua` — Change `local GameScene = require("game/scenes/game_scene")` and `manager:switch(GameScene.new())` to `local LevelScene = require("game/scenes/level_scene")` and `manager:switch(LevelScene.new(1, nil, manager))`.

- [x] Task F — `tests/test_scene.lua` — Update the two `GameScene` references (`require("game/scenes/game_scene")`, `GameScene.new()`) to `LevelScene` / `require("game/scenes/level_scene")`, constructing it as `LevelScene.new(1, nil, sm)` where `sm` is a fresh `SceneManager.new(1280,720)` local to the test (the existing dimension-threading assertions stay the same otherwise).

- [x] Task G — `tests/test_basics.lua` — Update the comment and `require("game/scenes/game_scene")` call to `game/scenes/level_scene`, constructing `LevelScene.new(1, nil, ctx.sm)` inside the `runner.setup` factory (factory already receives `sm` as its second arg).

- [x] Task H — `tests/test_player.lua` — New headless test file (plain assertions, no `love` calls beyond what stubs provide) covering the orbit algorithm in `game/player.lua`: (1) re-pivoting on a radius change leaves `x,y` unchanged and updates `center_x,center_y` to the new radius along the same line; (2) one `update()` call with radius held constant advances `angle` and moves `x,y` along the circle by the expected amount for the given `dt`; (3) radius clamps at `MIN_RADIUS`/`MAX_RADIUS` and won't go beyond regardless of how long space is held/released; (4) a collision against a wall rect flips `direction` and leaves the ball on the correct side of the wall.

- [x] Task I — `tests/test_level.lua` — New headless test file covering `game/level.lua`: (1) `Level.walls` returns the correct number of rects and none of them cover the exit gap span; (2) `Level.mirrored_entry` returns the opposite side at the same `pos` for each of the 4 sides; (3) `Level.spawn` places the ball inside the bounds, on the correct side, at the given `pos`, with `center` offset inward by `MIN_RADIUS`.

## Verification notes

- Algorithmic playthrough simulation (bypassing the real `love` window, run via `luajit` directly against `game/player.lua` + `game/level.lua`) caught a real bug not covered by the checklist as originally written: `LevelScene`'s level-1 default spawn used `Level.spawn({side="bottom", pos=640})`, but level 1's own bottom wall has no gap there (only the top does), so the ball spawned embedded in solid wall and was immediately shoved out of bounds on frame one. Fixed by adding `Level.default_spawn()` — a spawn point placed clear of any wall, used whenever there's no previous level's exit to mirror from (level 1's boot, and the level-3→level-1 loop). `game/level.lua` and `game/scenes/level_scene.lua` were both touched for this; a regression test (`Level.default_spawn()` lands outside every wall rect) was added to `tests/test_level.lua`.
- Could not visually play-test in a real window — this sandbox has no display (`DISPLAY` unset, `XDG_RUNTIME_DIR` invalid). Verification instead ran the full headless test suite (`love . --headless`, 5/5 files pass) plus standalone algorithmic simulations of level 1 with scripted space-hold strategies, confirming the ball can traverse a meaningful fraction of the room toward the exit gap under simple reactive control — consistent with (not a substitute for) real play. Actual feel/difficulty tuning (`RADIUS_RATE`, `ANGULAR_SPEED`, `MIN_RADIUS`/`MAX_RADIUS`, the level-3 choke-point width) should be revisited once someone can run the game in a window.
