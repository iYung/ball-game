# Puzzle Editor Checklist

Design doc: [docs/design/puzzle-editor.md](../design/puzzle-editor.md)

---

- [x] Task 1 — `lua/game/scenes/matrix_scene.lua` — Add optional `back_scene` fourth parameter to `MatrixScene.new`; store it on `self._back_scene`. Add `MatrixScene.new_from_def(puzzle_def, scene_manager, back_scene)` factory that stores `puzzle_def` on `self._custom_puzzle` and sets `_start_puzzle = nil`. In `load_puzzle`, when `self._custom_puzzle` is set load from it instead of calling `PuzzleLoader.load(n)`. In `_cmd_activate("menu")`, when `self._back_scene` is set call `self._scene_manager:switch(self._back_scene)` instead of switching to LevelSelectScene.

- [x] Task 2 — `lua/game/scenes/start_scene.lua` — Add a third button `start:editor` (label "Editor") at rect `{ x = W/2 - 60, y = 650, w = 120, h = 22 }`. Add it to `ui_elements()` after `start:unlock_all`. In `mouse_pressed`, route clicks on `start:editor` to `EditorScene.new(self._scene_manager)`. In `draw`, print "Editor" at that position. Requires Task 3 (EditorScene) to exist.

- [x] Task 3 — `lua/game/scenes/editor_scene.lua` (new file) — Create the EditorScene with these layout constants (matching MatrixScene): `GRID_X=95`, `GRID_Y=20`, `CELL_SIZE=63`, `PALETTE_Y=660`, `HUD_X=820`, `W=1280`, `H=720`. Implement: `EditorScene.new(scene_manager)` constructor that initialises a 10×10 `Grid`, default 2×2 input/target matrices filled with identity, empty name `""`, empty `_locked_tiles` list, all-off op allowlist, `_lock_mode=false`, palette selection `nil`; `on_enter` creates fonts; `ui_elements()` returning at minimum `editor:back` (label "Back", rect near bottom-right), `editor:test`, `editor:copy`, `editor:paste`; `mouse_pressed` routing `editor:back` to `StartScene.new(sm)`; `draw` drawing the dark background and checkerboard grid (same cell colours as MatrixScene) with tiles (source=green, sink=blue, gap=dark-red, op=tan with label); `update` is a no-op. All ops from MatrixScene's `PALETTE_BUTTONS` list appear in the bottom palette bar as `editor:pal:<kind>` buttons; eraser as `editor:pal:erase`; lock toggle as `editor:lock`. `mouse_pressed` routes palette clicks to set `_sel` and routes grid clicks to place/clear tiles: left-click places the selected tool, right-click clears.

- [x] Task 4 — `lua/game/scenes/editor_scene.lua` — Add the HUD panel (x=820, w=460): (a) **Name field** — a rect `editor:name` (kind `"button"`) at the top of the HUD; clicking it sets `_name_focus=true`; `text_input(ch)` appends to `_name` when focused; `key_pressed("backspace")` removes last char; `key_pressed("return"/"escape")` unfocuses. Draw the name text in the HUD. (b) **Matrix editors** — INPUT section: `editor:input_rows_dec`, `editor:input_rows_inc`, `editor:input_cols_dec`, `editor:input_cols_inc` buttons; `editor:input_cell:<r>,<c>` cell elements for every matrix cell, left-third click decrements value, right-third click increments (clamp –9..9), centre click does the same as left for now. Same layout for TARGET. (c) **Op allowlist** — a compact list of toggle buttons `editor:allow:<op>` for each op name in `OP_NAMES` (same order as PALETTE_BUTTONS); toggling adds/removes the op from `_allowed_ops`. Draw all HUD sections. All new elements appear in `ui_elements()`.

- [x] Task 5 — `lua/game/scenes/editor_scene.lua` — Implement **Copy**: `_serialize(self)` returns a Lua source string in the same format as `data/puzzles/*.lua` (fields: `name`, `grid_w=10`, `grid_h=10`, `source`, `sink`, `input`, `target`, `gaps` if any, `ops` if `_allowed_ops` is non-empty and not every op, `locked` if any locked op/pusher tiles). The Copy button calls `love.system.setClipboardText(_serialize(self))` and sets `_copy_flash = 1.0` (a countdown timer shown as "Copied!" text in draw). `update(dt)` decrements `_copy_flash` to 0.

- [x] Task 6 — `lua/game/scenes/editor_scene.lua` — Implement **Paste**: the Paste button calls `love.system.getClipboardText()`, wraps it as `"return " .. text`, calls `load(wrapped)`, pcalls the result, and if successful calls `_load_def(self, def)` which resets the grid, matrices, name, gaps, locked tiles, and allowlist from the parsed table (same logic path as `new` but reading from `def`). On parse error, sets `_paste_error = "Parse error"` shown briefly in draw (same flash approach as copy).

- [x] Task 7 — `lua/game/scenes/editor_scene.lua` — Implement **Test**: the Test button builds a puzzle table via `_build_def(self)` (same as `_serialize` but as a table, not a string), then calls `local ms = require("lua/game/scenes/matrix_scene"); self._scene_manager:switch(ms.new_from_def(def, self._scene_manager, self))`. Requires Task 1 (new_from_def) to be complete.

- [x] Task 8 — `tests/ui/12_editor.lua` (new file) — Write a UI spec (or list of specs) that: (1) navigates from start screen → editor via the "Editor" button; (2) places a source, sink, gap and one op tile on the grid; (3) sets input/target matrix values; (4) clicks Copy and asserts "Copied!" flash text appears; (5) clicks Test and asserts the puzzle scene loads (assert_text the puzzle name or "INPUT" HUD text); (6) presses the Menu/Back key to return to the editor. Each scenario is a separate spec in the list. Drive everything through `click_button` / `click_cell` / `press` only — no private method calls.
