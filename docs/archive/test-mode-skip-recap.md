Design: `docs/design/test-mode-skip-recap.md`. Run order: A, then B, then C (sequential; A and B edit the same file, and C needs both to pass).

- [x] Task A — `lua/game/scenes/matrix_scene.lua` — Add one private method (e.g. `MatrixScene:_leave()`) that switches to `self._back_scene` when it is set, and otherwise to `LevelSelectScene.new(self._scene_manager, self._settings_state)` (keep the `require` inside the function, as now). Use it in both places that leave the puzzle: the `"menu"` branch of `_cmd_activate` (keep the existing `if self._scene_manager` guard) and the exit callback passed to `SettingsMenu.new` in `on_enter`. Result: in Test mode, Settings "Exit to Menu" returns to the same editor scene; normal play still goes to level select. Switch to the existing `_back_scene` object, never a new `EditorScene`, so the draft is kept. Do not change `settings_menu.lua` (it already saves volumes and stops the music before calling the callback) or `editor_scene.lua`.

- [x] Task B (depends on A) — `lua/game/scenes/matrix_scene.lua` — In the `"continue"` branch of `_cmd_activate`, when `self._back_scene` is set, call `self:_leave()` and do not require, build or switch to `SolutionRecapScene` (so a test win records nothing in saved progress). Without `_back_scene`, behavior is unchanged. The `return` key already goes through this branch, so `key_pressed` needs no change. Leave the `WIN!` banner, `_cmd_enabled`, and the button's label and position as they are.

- [x] Task C (depends on A and B) — `tests/ui/19_editor_test_mode.lua` (new file) — UI specs using real input only (see `docs/testing.md`; no private scene methods; do not edit any existing test or spec).
